# ADR 0002：代理认证凭据传输边界

**修订号：** r1  
**状态：** 生效  
**日期：** 2026-09-21  
**适用范围：** v0.1 个人本地客户端  
**关联文档：** [v0.1 执行文档](../versions/v0.1-execution-r6.md)、[风险登记](../risk-register.md)

## 背景

v0.1 支持 HTTP、HTTPS 和 SOCKS5 代理以及用户名/密码认证。将解密后的密码拼入 Chromium 的 `--proxy-server` 命令行会让本机其他进程、诊断工具或用户可见的进程信息读取到凭据。代理密码只能保存在操作系统安全存储中，不能进入 SQLite、日志、URL 或浏览器进程命令行。

## 决定

1. 浏览器启动参数只包含代理协议、主机和端口，不包含用户名和密码。
2. 代理密码继续使用 Electron `safeStorage` 保存；启动 Worker 任务时由 Main 进程按环境引用即时读取。
3. Main 进程通过 Worker 的标准输入传递一次性任务 payload；凭据不放在命令行参数、环境变量或日志中。
4. Worker 使用 Chromium CDP `Fetch.authRequired` 处理来源为 `Proxy` 的认证挑战，并调用 `Fetch.continueWithAuth` 提供凭据。
5. Worker 任务结束、失败或取消后释放子进程；凭据只存在于本次 Main/Worker 内存生命周期中。
6. 系统安全存储不可用或凭据无法解密时，任务必须失败并显示可理解的错误，不得回退到明文存储或命令行注入。

## 影响

- 浏览器进程命令行不再暴露代理密码，降低同机进程观察风险。
- 代理认证依赖 Chromium CDP 和 Worker 的生命周期；不支持 CDP 的内核不能宣称支持该认证路径。
- v0.1 的端到端验证覆盖标准 Chromium 的打包 Worker 控制链路；真实认证代理矩阵仍需在后续验收中使用专用测试代理补充。
- 未来接入 Firefox、Juggler 或远程执行时，必须为对应协议重新定义凭据传输和审计边界，不能复用本决定的实现假设。

## 退出条件

如果目标内核无法可靠处理 CDP 代理认证挑战，或需要跨设备/团队同步凭据，则应创建新的 ADR，评估本地认证桥接、客户端加密或服务端密钥管理；不得静默恢复命令行密码注入。

## 变更记录

- `r1`：确定 v0.1 代理认证不进入浏览器命令行，改用安全存储到 Worker 标准输入再由 CDP 处理。
