- 实现基于独占目录的环境运行锁、启动恢复、异常退出标记和手动恢复 IPC。
- 实现 Kernel Registry、Chromium 启动参数、标准 Chromium 本机探测和 SHA-256/原子安装器。
- 使用 Electron `safeStorage` 保存代理凭据；普通 SQLite 只保存 credential reference。
- 实现 Worker smoke task：CDP 连接、打开 URL、读取标题、截图和取消入口。
- 增加 contracts、kernel 参数、安装校验、SQLite、运行锁和 Worker protocol 单元测试。
- 增加 CI、Windows/macOS 构建和 tag Release workflow 草稿。
- 解决 `electron-vite` 配置文件命名、renderer root、输出目录和 workspace 包打包问题。
- 代理启动参数改为只包含代理地址；代理密码通过 `safeStorage`、Worker 标准输入和 CDP `Fetch.authRequired` 传递，避免进入浏览器命令行。
- Worker 取消入口返回结构化 `CANCELLED` 结果，并补充打包 Worker 的标准输入协议。
- Windows NSIS 与 portable 产物使用不同文件名，避免构建产物互相覆盖；打包时排除 workspace 包的 TypeScript 源文件。
- 完成 Windows x64 打包 Worker 端到端 smoke：独立 Chrome CDP、`https://example.com`、标题读取和 PNG 截图均成功。

## 当前限制

实现必须严格遵循 `docs/versions/v0.1-execution-r2.md`；在用户最终验收和所有发布门禁通过前，不得创建正式 Release tag 或推送 GitHub Release。

- v0.1 使用 Electron/Node `node:sqlite` 运行时，详见 [ADR 0001](../adr/0001-local-sqlite-runtime.md)；Node 22 下测试会显示实验性警告。
- fingerprint-chromium 只注册适配器和专属参数 schema，尚未配置可分发的内核下载地址、许可证和哈希。
- 标准 Chromium 只探测用户本机 Chrome、Edge 或 Chromium，不随安装包分发专有浏览器二进制。
- 当前本机已完成 Windows x64 未压缩目录构建和启动检查；macOS 产物尚未在本机验证。
- v0.1 不包含团队 API、PostgreSQL、WebUI、工作流、LangChain/LangGraph、RAG、远程执行和备份同步。
