## 已完成

- 创建并维护 `AGENTS.md`、版本分析、执行文档、ADR、兼容矩阵、风险登记和进度证据。
- 初始化 pnpm workspace、Electron 44、React 19、TypeScript、Vite 7、electron-vite 和 electron-builder 基线。
- 使用官方 shadcn/ui `base-nova` 与 Base UI primitives，移除 Radix UI 直接依赖；按官方 `sidebar-07` 结构使用 `SidebarProvider`、`SidebarInset`、可收缩侧栏和官方空白主体组合。
- 完成个人环境、代理、内核、设置、Worker smoke 的本地 UI 和类型化 Preload/IPC 闭环。
- 主题系统支持 light/dark/system、颜色预设、圆角、密度、字体和 Sidebar 布局，并通过版本化 contracts、受限 IPC 和 SQLite 设置持久化。
- 完成 SQLite migration、环境和代理元数据、内核 Registry/Adapter、独占运行锁、恢复状态和 Worker CDP 控制链路。
- 使用 Electron `safeStorage` 保存代理凭据；代理密码不进入浏览器命令行、URL、环境变量或日志，按 ADR 0002 通过 Worker 标准输入和 CDP 认证挑战传递。
- 工程正式门禁为 Prettier、ESLint、TypeScript 和 Vitest；Oxlint/Oxfmt 保留为渐进试运行，不替换 Electron 根链路。
- 补齐 `.github/workflows/ci.yml`、`build-desktop.yml`、`release.yml`，覆盖检查、Windows x64、macOS arm64/x64 构建、SHA-256 和 tag Release 发布。
- 修正 Windows workflow 使用 `Get-FileHash.Path` 生成资产文件名；alpha.4 的 Windows 校验文件现在包含哈希和对应文件名。

## 自动化验证

本地在 macOS arm64、Node.js 22.15.0、pnpm 10.26.2 下通过：

```text
pnpm install --frozen-lockfile
pnpm check
pnpm --filter @contextweave/desktop exec electron-vite build
git diff --check
```

`pnpm check` 包含 Prettier、ESLint、TypeScript 和 Vitest；所有 workspace 测试通过。SQLite 测试只产生 Node `node:sqlite` 实验性警告，不影响退出码。三个 workflow 文件通过 Ruby YAML 解析。

## 仍未关闭的验收项和已知限制

- `fingerprint-chromium` 当前只有适配器、配置 schema 和未配置 manifest；没有已确认来源、许可证、下载 URL 和 SHA-256，因此不能宣称可下载或分发该内核。标准 Chromium 只探测用户本机已有且用户有权使用的 Chromium/Chrome/Edge。
- 已完成标准 Chromium 的打包 Worker CDP smoke；使用专用测试代理完成 HTTP、HTTPS、SOCKS5 认证矩阵仍待后续验收。
- 桌面 UI 自动化、异常退出的跨平台手动矩阵、低磁盘和下载中断测试尚未全部自动化覆盖。
- 本机 macOS arm64 的 `electron-builder --dir` 曾在 packaging 阶段长时间无输出而中止；三个目标平台的 CI Release 构建均已通过，因此 CI 是本轮 macOS 产物证据来源。
- Release 产物未签名或公证，首次启动可能需要按系统提示手动放行。
- v0.1 不包含团队 API、PostgreSQL、WebUI、工作流、LangChain/LangGraph、RAG、远程执行、备份同步或完整指纹隐身承诺。
