## 1. 用户价值和版本目标

用户可以从 GitHub Release 下载未签名的 ContextWeave 客户端，在自己的 Windows 或 macOS 电脑上：

1. 创建一个个人浏览器环境。
2. 选择一个已注册的浏览器内核。
3. 下载并校验内核。
4. 配置代理和最小环境参数。
5. 启动、使用、查看状态并停止独立浏览器进程。
6. 使用一个最小 TypeScript Worker 任务验证浏览器控制链路。
7. 关闭客户端后再次启动，恢复环境元数据和可解释的运行状态。

v0.1 的重点是验证桌面协调层、环境生命周期、内核适配边界和发布链路，为后续个人环境管理、团队服务和环境接力提供稳定基础。

## 2. 已确认的范围决定

| 项目 | 决定 |
|---|---|
| 工作空间 | 只实现个人本地模式；不实现团队 API、PostgreSQL、成员和租约 |
| 桌面基线 | `electron-vite` 稳定组合 + React + TypeScript + Vite 7 + electron-builder |
| UI 基线 | shadcn/ui `base-nova` + Base UI；使用当前 shadcn CLI 生成的 `cn` 工具，不再使用 Radix UI |
| 内核 | `fingerprint-chromium` + 标准 Chromium 适配器 |
| Chrome/Edge | 不随项目分发专有二进制；本机探测属于可选能力，不作为 v0.1 必验下载内核 |
| 平台 | Windows x64、macOS arm64、macOS x64；Linux 不纳入 v0.1 验收 |
| 代理 | HTTP、HTTPS、SOCKS5 和认证；每个环境一个代理；不做代理池和自动轮换 |
| 最小指纹 | 语言、时区、User-Agent/Client Hints、平台、窗口尺寸、硬件并发数、WebRTC/DNS 策略 |
| Worker | 打开 URL、读取标题、截图、停止；不实现工作流画布和 AI |
| 敏感数据 | 仅本地保存，敏感值通过操作系统安全存储；v0.1 不同步 Cookie/会话 |
| 环境目录 | 默认系统应用数据目录，允许修改根目录，迁移前检查和失败回滚 |
| 发布 | Windows NSIS/可选便携包，macOS DMG/ZIP；不签名、不公证、不自动更新 |
| 性能 | 建立启动、内存、下载和稳定性基线，暂不设硬性数值门槛 |
| 语言 | 中文默认，保留 i18n 结构 |
| 发布通道 | 首次可下载版本为 `v0.1.0-alpha.1` 或 preview，明确实验性和支持矩阵 |

## 3. 本版本包含的功能

### 3.1 桌面客户端基础

- Electron 主进程、Preload 和 React Renderer 分离。
- `contextIsolation`、Renderer sandbox、禁用远程页面 Node.js 能力和基础 CSP。
- shadcn/ui `base-nova` 官方 `sidebar-07` block：使用 CLI 生成的示例侧栏组件和官方空白主体占位；环境、代理、内核和设置业务页面暂不放入 Renderer。
- 第一版主题系统：主题模式、主题颜色预设、圆角、界面密度、字体和官方 Sidebar 布局变体；所有选项通过 shadcn CSS variables 和 Base UI 组件生效。
- 侧栏布局变体只使用官方 Sidebar primitives 的受控组合（例如 `icon`、`offcanvas`、`inset` 等折叠/容器行为），共享同一导航数据契约，不复制业务页面结构。
- 主题偏好作为全局应用设置保存，不绑定单个浏览器环境；启动时在首次 Renderer 绘制前恢复，支持恢复默认值。
- Base UI primitive 与当前 shadcn/ui 组件源保持一致；组件通过本地复制源码维护。
- 中文默认文案和最小 i18n 资源结构。
- 全局任务/浏览器状态入口，异步结果按当前环境 ID 校验，避免串显示。
- 应用数据目录、环境根目录、日志目录和内核安装目录的显示与配置。

### 3.2 本地数据和环境模型

使用 SQLite 保存元数据，推荐 `better-sqlite3 + Drizzle`。v0.1 至少包含以下实体：

- `environments`：环境 ID、名称、状态、内核引用、代理引用、配置版本、数据目录、创建和更新时间。
- `kernel_installations`：内核 ID、版本、平台、架构、来源、SHA-256、安装路径和安装状态。
- `proxies`：代理 ID、协议、主机、端口和凭据引用；密码不直接写入 SQLite。
- `app_settings`：语言、环境根目录、内核目录和日志级别。
- `runtime_sessions`：启动会话、PID、控制端口、启动时间、退出原因和状态。

SQLite migration 必须可重复执行，数据库损坏或迁移失败时不能静默覆盖原文件。v0.1 不创建团队表、租约表、PostgreSQL schema 或对象存储表。

### 3.3 浏览器内核 Registry 和 Adapter

实现以下边界：

```text
Kernel Registry
    ├── 读取版本化 manifest
    ├── 匹配平台和架构
    ├── 下载临时文件
    ├── 校验 SHA-256
    ├── 原子安装
    └── 提供已安装版本

Kernel Adapter
    ├── 校验通用配置和内核专属配置
    ├── 生成启动计划
    ├── 启动和连接外部进程
    ├── 查询能力
    └── 停止和清理
```

每个内核必须有独立的 manifest、配置 schema、adapter 和测试。标准 Chromium 适配器允许使用项目维护的合法 manifest 或用户指定的本地可执行文件；不能默认下载或分发 Google Chrome、Microsoft Edge 专有二进制。

manifest 至少记录：内核 ID、家族、版本、平台、架构、可执行文件、下载 URL、SHA-256、控制协议、能力签名、配置 schema、数据目录兼容范围、来源和许可证。

内核启用前必须完成来源、许可证、下载地址、哈希和安全更新责任检查。未完成检查的 manifest 只能用于开发测试，不能进入 Release。

### 3.4 环境生命周期

环境状态至少包括：`created`、`ready`、`starting`、`running`、`stopping`、`stopped`、`error`、`needs-recovery`。

启动流程：

```text
读取环境
→ 检查内核安装和配置
→ 检查环境锁
→ 创建独立用户目录
→ 分配 loopback 控制端口
→ 生成内核启动计划
→ 启动外部浏览器
→ 连接 CDP/适配器协议
→ 写入 runtime session
→ 更新为 running
```

停止流程：

```text
请求停止
→ 停止 Worker 任务
→ 关闭浏览器页面或进程
→ 等待退出
→ 清理控制端口和运行锁
→ 写入退出原因
→ 更新为 stopped
```

异常流程必须覆盖：下载中断、哈希错误、配置错误、端口占用、启动失败、进程崩溃、重复启动、强制关闭和客户端异常退出。运行中的环境不能被误判为可安全接管。

### 3.5 代理和最小环境配置

v0.1 支持：

- HTTP、HTTPS、SOCKS5。
- 用户名和密码认证。
- 每个环境绑定一个代理。
- 启动前代理格式校验和基本连通性检查。
- 语言、时区、User-Agent/Client Hints、平台、窗口尺寸、硬件并发数和 WebRTC/DNS 策略。

v0.1 不实现代理池、自动轮换、批量导入、代理评分和自动选择。对于内核未验证的 Canvas、Audio、WebGL、字体等能力，界面必须显示“不保证”或不提供该配置项。

### 3.6 Worker 最小任务

Worker 作为独立 TypeScript 进程运行，不能依赖 React 组件生命周期。任务输入和事件使用版本化结构：

```text
start → openUrl → readTitle → screenshot → stop → completed
```

每个任务必须支持：成功、参数错误、超时、取消、浏览器不可用和异常退出。事件至少包含任务 ID、环境 ID、步骤、时间、状态、错误代码和脱敏消息。v0.1 不做可视化工作流、节点市场、AI 调用、批量环境和远程执行。

## 5. IPC、协议和安全要求

- Renderer 只能调用 Preload 暴露的白名单 API。
- IPC 输入使用 Zod 或等价运行时 schema 校验，返回值也必须校验。
- Renderer 不接收任意文件路径执行权限，不直接接收任意 CDP 端口连接权限。
- Main 负责窗口、文件选择、环境协调和外部进程生命周期，不承载长时间业务逻辑。
- Worker 使用受限消息协议，不获得文件系统根目录、数据库超级权限或任意 shell 权限。
- 浏览器用户目录与 Electron session 完全分离。
- 代理密码、Cookie、会话数据和其他凭据通过 `CredentialStore` 抽象保存；优先验证 `keytar` 与目标 Electron ABI 的兼容性，不能兼容时不得回退到明文日志或明文配置。
- 下载的内核经过 HTTPS、平台/架构校验、SHA-256 和原子安装后才能执行。
- 日志不记录 Authorization、Cookie、代理密码、表单值、模型密钥和完整页面内容。

### 6.2 集成和手动验收

- Windows x64：创建环境、下载内核、启动/停止浏览器、Worker 任务和异常恢复。
- macOS arm64：同上。
- macOS x64：构建并完成启动验证。
- 两个内核分别验证独立用户目录、代理参数、窗口参数、控制协议和停止清理。

## 7. 验收标准

版本候选至少满足：

1. 用户无需安装 Node.js、Python 或开发工具即可启动客户端。
2. 可以创建个人环境，并保证环境数据目录互不串用。
3. `fingerprint-chromium` 和标准 Chromium 两个适配器均可注册、校验、安装/发现、启动、连接和停止。
4. 内核下载失败、哈希错误、代理失败、启动失败、浏览器崩溃和重复启动都有可理解的错误和安全清理行为。
5. 不支持的内核参数在启动前被拒绝或明确提示，不静默伪装成已生效。
6. Worker 可以完成打开 URL、读取标题、截图和停止，并能验证超时、取消和失败事件。
7. 应用重新启动后可以恢复环境元数据和上次运行状态；运行中的环境不会被误判为可安全接管。
8. Windows x64、macOS arm64 和 macOS x64 的构建流程完成；Windows/macOS 产物均生成 SHA-256。
9. 关键测试、构建日志摘要、产物哈希、支持矩阵和已知限制写入 `docs/progress/v0.1.md`。
10. 用户完成 v0.1 alpha/preview 的最终验收。

## 10. 回滚和恢复

- 内核下载失败：删除临时文件，保留原已安装版本。
- 内核升级失败：不切换当前有效版本，恢复之前的安装记录。
- 环境目录迁移失败：保留旧目录，删除临时目标目录，恢复设置。
- SQLite migration 失败：停止启动流程，保留数据库副本并显示恢复指引。
- 浏览器异常退出：清理运行锁和控制端口，标记环境为 `needs-recovery`，不自动覆盖用户目录。
- Worker 超时或取消：终止子进程，释放浏览器资源，写入可重试的任务结果。
- Release 构建失败：不创建成功 tag，不上传伪造或不完整产物。

## 11. 已知限制和风险

- v0.1 不提供团队协作、跨设备同步和环境接力。
- v0.1 不保证所有网站、所有指纹检测工具或所有内核参数的行为。
- macOS 未签名安装可能出现系统警告；Release 提供手动放行和 SHA-256 说明。
- 第三方内核来源、许可证、下载地址和安全更新责任必须在实现时逐项确认。
- `better-sqlite3`、`keytar` 等原生模块需要按 Electron ABI rebuild，并在 Windows/macOS CI 中验证。
- 标准 Chromium 与 fingerprint-chromium 的用户目录不保证跨版本直接恢复；环境必须记录内核版本和兼容范围。
